## 🟠 问题 2: `git pull` 报错 `Not possible to fast-forward, aborting`

- 【**问题描述**】执行 `git pull` 时失败，报错为 `fatal: Not possible to fast-forward, aborting.`，导致无法同步远端更新。
- 【**问题环境**】分支：`dev`；Git 配置：`pull.ff=only`。
- 【**问题分析**】本地分支与远端分支发生分叉，状态为 ahead 1、behind 2。`pull.ff=only` 只允许快进合并，不允许在分叉场景自动 merge，因此 `git pull` 被拒绝。
- 【**问题状态**】✅ 已定位 / ⏳ 处理中
- 【**问题方案**】采用允许 merge 的处理方式

```bash
git fetch origin
git merge origin/dev
git push
```

- 【**知识总结**】当开启 `pull.ff=only` 时，`git pull` 在“本地和远端均有新提交”的分叉场景会直接失败；更稳妥的日常流程是 `fetch + rebase`。`

- [ ] Rviz2 可视化 SLAM 建图的最小学习步骤（参照小鱼ROS2书籍）

根据书中提供的内容结构，特别是第6章（建模仿真）、第7章（自主导航）和第9章（实体机器人搭建）的目录逻辑，要让你的车在RViz2中实现SLAM建图，通常需要依次完成以下步骤：

1. 创建并准备机器人模型 (URDF)

对应章节：6.2 使用 URDF 创建机器人 & 9.5.3 准备机器人 URDF
步骤说明：首先需要为你的机器人创建URDF模型文件，描述其结构、关节和传感器等信息。如果是实体机器人，同样需要准备URDF文件以便在ROS 2系统中描述它。

2. 添加激光雷达传感器并获取数据

对应章节：6.4.5 激光雷达传感器仿真 & 9.5.1 驱动并显示雷达点云
步骤说明：SLAM建图依赖激光雷达数据。如果是仿真环境，需要在Gazebo中为机器人添加激光雷达插件；如果是实体机器人，需要驱动雷达并发布雷达点云话题。

3. 配置坐标系与发布里程计TF

对应章节：5.1 坐标变换工具介绍 & 9.5.2 移动机器人的坐标系框架介绍 & 9.5.4 发布里程计 TF
步骤说明：SLAM算法需要知道机器人各部件之间的位置关系以及机器人随时间的移动轨迹。必须正确配置机器人的坐标系框架，并发布里程计的TF变换。

4. 使用 slam_toolbox 进行建图

对应章节：7.2.1 构建第一张导航地图
步骤说明：启动 slam_toolbox 节点，订阅雷达和里程计数据，开始构建地图。

5. 在 RViz2 中可视化建图过程

对应章节：5.4.2 数据可视化工具 RViz
步骤说明：打开RViz2，添加Map显示插件订阅地图话题，添加LaserScan显示插件订阅雷达数据，以及添加TF显示插件查看坐标系关系，从而实时观察SLAM建图的效果。

6. 保存地图

对应章节：7.2.2 将地图保存为文件 & 9.5.5 完成机器人建图并保存地图
步骤说明：建图完成后，将构建好的地图保存为文件，供后续导航使用。

总结流程：
准备URDF -> 驱动雷达发布点云 -> 发布里程计TF -> 启动slam_toolbox -> 使用RViz2可视化 -> 保存地图。
