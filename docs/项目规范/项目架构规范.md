# 架构深度

## 🏔️ 顶层架构（项目整体视角）

**目标**：让任何一个外部人或新成员，一看就知道“系统是干什么的、主要组成部分是什么、它们怎么协同”。  
它应该覆盖 **全局五维度**，但只需要 **宏观到能看懂，不要过细**。

1. **功能分层**（做什么）
    
    - 应用层：BCI / MR / 高层任务规划
        
    - 决策层：任务分发、路径规划、调度
        
    - 功能层：SLAM、感知、避障
        
    - 执行层：底盘、机械臂、末端
        
    - 支持层：ROS2、服务器、仿真
        
2. **关键模块**（谁来做）
    
    - 每层只挑 2~3 个核心模块写出
        
    - 例如 “SLAM” 而不是 “Cartographer vs. Fast-LIO”
        
3. **核心数据流**（怎么连）
    
    - 一个主链路：传感器 → 感知 → 决策 → 执行 → 反馈
        
    - 辅助链路：人机交互（BCI/MR → 任务分发）
        
4. **部署映射**（在哪跑）
    
    - RDK X5 跑驱动与感知节点
        
    - PC 服务器跑 SLAM、导航、仿真
        
    - MR/BCI 设备作为上层交互端
        
5. **演进阶段**（什么时候做）
    
    - 阶段1：底盘自主导航
        
    - 阶段2：机械臂协同操作
        
    - 阶段3：BCI/MR 融合
        

👉 顶层架构文档要用 **一张总览图 + 一张部署图 + 一张阶段演进表** 就够了。

---

## 🛠️ 组内架构（机械/电子/软件组视角）

**目标**：让组员明确自己“负责的模块范围、内部细节、对外接口”。  
这里依然用 **功能 / 模块 / 数据流 / 部署 / 演进** 五维度，但粒度更细，强调组内落地。

---

### 🔧 机械组架构需要描述：

- **功能**：承载、移动、操作（底盘、机械臂、末端）
    
- **模块**：底盘结构、传动机构、机械臂关节、末端工具
    
- **数据流**：电机控制量输入（CAN/PWM）→ 运动 → 反馈传感器（里程计、角度传感器）
    
- **部署**：硬件 BOM（电机、舵机、传感器）、控制接口对接点
    
- **演进**：先出基础底盘样机 → 加装机械臂 → 集成末端执行器
    

---

### ⚡ 电子组架构需要描述：

- **功能**：动力驱动、电源管理、传感器接入、通信接口
    
- **模块**：电机驱动板、IMU/LiDAR/相机接口、CAN/UART/USB总线
    
- **数据流**：ROS2 节点与硬件接口之间的信号流（cmd_vel → 电机控制，odom → 上报）
    
- **部署**：板卡分布、供电结构、通信拓扑图
    
- **演进**：先实现底盘驱动电路 → 扩展传感器接口 → 加入机械臂控制
    

---

### 💻 软件组架构需要描述：

- **功能**：算法实现、系统调度、人机交互
    
- **模块**：SLAM节点、Nav2、任务分发节点、机械臂控制节点、BCI/MR接口节点
    
- **数据流**：ROS2 Topic/Service/Action 说明（输入、输出、消息类型）
    
- **部署**：哪些节点跑在 RDK X5，哪些跑在 PC，哪些跑在 MR/BCI
    
- **演进**：阶段性目标（先实现 SLAM+Nav2 → 再集成机械臂 → 再对接 BCI/MR）
    

---


- **顶层架构**：全局分层 + 关键模块 + 主数据流 + 部署映射 + 演进阶段
    
- **组内架构**：围绕五维度展开，但粒度更细，强调 **本组内部结构** 和 **对外接口**
    

这样，你就能既有 **统一性**（五维度框架），又有 **分工清晰度**（顶层 vs 组内）。

# 架构维度

## 1. 功能架构 (Function Layering)


## 2. 分层架构（System Layering）

**目标**：整体视角，明确系统大框架  
**内容要点**：

- 各层的定义（应用层、决策层、功能层、执行层、支持层）
    
- 每层的职责与边界
    
- 层与层之间的依赖关系
    

**示例结构**：

```
应用层：任务规划、BCI/MR交互
决策层：路径规划、任务调度
功能层：SLAM、感知融合、避障
执行层：底盘、机械臂、末端执行器
支持层：ROS2、通信中间件、开发服务器、仿真环境
```

---

## 3. 模块架构（Module Architecture）

**目标**：细化到每个功能点，利于分工和迭代  
**内容要点**：

- 每个模块的名称、职责
    
- 输入、输出、依赖（其他模块/硬件）
    
- 模块间的接口（函数/消息/协议）
    

**表格示例**：

|模块名称|输入|输出|依赖|说明|
|---|---|---|---|---|
|SLAM节点|激光雷达/IMU数据|地图 / 里程计|ROS2 DDS|建图与定位|
|Nav2导航|地图、目标点|控制指令|SLAM模块|全局+局部路径规划|
|底盘驱动|控制指令|电机转速 / 反馈|CAN总线|实现移动闭环控制|

---

## 4. 数据流架构（Data Flow）

**目标**：明确信息如何流动，保障接口清晰  
**内容要点**：

- 主数据流：传感器 → 感知算法 → 决策 → 执行 → 反馈
    
- 辅助数据流：日志、状态监控、人机交互
    
- 标明消息类型（ROS2 Topic/Service/Action）
    

**示例图结构**：

```
[激光雷达] --/scan--> [SLAM] --/map, odom--> [Nav2] --/cmd_vel--> [底盘驱动] --/odom--> [Nav2]
```


---

## 5. 部署架构（Deployment）

**目标**：落实到硬件与环境，指导实际搭建  
**内容要点**：

- 硬件分布（RDK X5、PC服务器、MR设备）
    
- 软件环境（ROS2 Humble、Gazebo、RViz2）
    
- 通信方式（SSH、VNC、VPN、ROS2 DDS）
    
- 部署示意图
    

**示例表格**：

|硬件/环境|运行模块|通信方式|
|---|---|---|
|RDK X5|底盘驱动节点、传感器驱动|CAN/USB|
|开发服务器PC|SLAM、Nav2、仿真|SSH/VNC|
|MR眼镜/BCI|高层任务交互|WiFi/ROS2|

✅ 总结：  
以后写架构时，你就按 **5个维度** 固定格式走：

1. 分层架构 → 总体框架
    
2. 模块架构 → 谁做什么
    
3. 数据流架构 → 数据怎么流
    
4. 时间架构 → 分阶段目标
    
5. 部署架构 → 环境和硬件落地
    

这样一份文档即完整又不乱，还能和你们的 **开发服务器规范**、**机械开发流程**对接起来。
