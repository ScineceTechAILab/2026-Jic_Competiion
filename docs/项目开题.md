# **一、选题背景与意义**

## **1.1  研究背景**

随着人工智能与机器人技术的快速发展，移动操作臂（Mobile Manipulator）系统已成为智能制造、物流分拣、医疗康复等领域的核心研究方向之一。与固定式机械臂相比，移动操作臂将自主移动能力与末端操作能力相结合，能够在非结构化环境中完成复杂的抓取与搬运任务，具有更高的实用价值与应用前景。

与此同时，脑机接口（Brain-Computer Interface，BCI）技术与混合现实（Mixed Reality，MR）技术近年来均取得了显著进展。非侵入式脑电设备成本持续降低，MR 眼镜（如 Meta Quest 3）的消费级普及为空间感知反馈提供了新的工程路径。然而，现有研究中 BCI、机器人、MR 三个技术栈大多各自独立发展，缺乏将三者整合为统一闭环系统的工程实践。

本课题拟在地瓜机器人 RDK X5 平台上，构建一套"BCI 意图接入层 — Agent 调度层 — 具身执行层 — MR 空间反馈层"四层闭合回路系统，实现从人脑意图出发、经机器人执行、再通过 MR 反馈回到人的认知系统的完整闭环，探索人机协同的新范式。

## **1.2  研究意义**

本课题的研究意义体现在以下三个层面：

- **工程验证意义：**通过完整实现四层闭环系统，验证 BCI、具身智能与 MR 三栈融合的工程可行性，为相关交叉研究提供可复现的原型系统与开源代码参考。

- **技术创新意义：**闭环设计使操作者成为回路中的有效调节环节——MR 空间反馈影响其注意力状态，进而通过 BCI 形成下一轮控制信号。这一"认知-执行闭环"是传统遥操作系统所不具备的特性。

- **应用前景意义：**研究成果可推广至行动障碍人士的辅助机器人、智能制造人机协作场景，以及面向新型人机交互的教育与科研平台，具有较高的社会价值与产业转化潜力。

# **二、国内外研究现状**

## **2.1  移动操作臂系统研究现状**

国际上，移动操作臂领域的代表性平台包括：PR2（Willow Garage）、HSR（Toyota）、TIAGo（PAL Robotics）等，这些系统已具备较完善的感知-规划-执行能力，但成本高昂，难以在教学与小规模研究场景推广。国内方面，松灵机器人、优必选等企业推出了面向科研的移动操作臂，但在模块化设计与跨平台兼容性上仍有提升空间。ROS2 框架下的 Nav2 与 MoveIt2 已成为学术研究的主流工具，为本课题提供了成熟的技术基础。

## **2.2  脑机接口与机器人控制研究现状**

BCI 驱动机器人控制主要分为两类：一类基于 P300、SSVEP 等离散诱发电位进行指令分类；另一类基于运动想象（MI）信号实现连续控制，但对信号质量要求高、个体差异显著。本课题采用连续专注度阈值作为触发信号，从架构层面规避了 EEG 个体差异导致的分类器泛化问题，在保证 Demo 稳定性的前提下提供了更具工程实用性的解决路径。

## **2.3  混合现实与机器人反馈**

MR 技术在机器人领域的应用已有初步探索，主要集中在远程遥操作（teleoperation）和工厂质检中的 AR 辅助标注。将 MR 作为机器人任务执行的实时反馈通道，并与 BCI 构成闭环的研究目前较为罕见。Meta Quest 3 作为国产 AR 眼镜，支持 Unity 开发，具备透视显示与空间感知能力，是在成本约束下实现 MR 反馈层的可行选型。

## **2.4  现有研究的不足与本课题切入点**

现有研究存在以下不足：其一，BCI、具身智能、MR 三个技术栈缺乏统一的工程接口设计与闭环整合；其二，MR 在机器人系统中大多作为可视化工具而非控制回路的有效组成部分；其三，移动操作臂末端执行器通常为固定配置，任务切换需要手动干预。本课题以四层闭环为核心命题，以工程可行性为首要约束，设计标准化接口，实现 BCI × 具身智能 × MR 的首次系统级闭环融合验证。

# **三、研究内容与目标**

## **3.1  研究内容**

本课题的研究内容分为以下六个模块：

- **移动底盘自主导航模块：**基于 RPLIDAR S1 激光雷达与 RDK X5 主控，集成 SLAM Toolbox 完成室内环境建图，配置 Nav2 导航栈实现点到点自主导航与动态避障。底盘驱动层已完成，本阶段重点在于 ROS2 节点封装与 Nav2 联调。

- **模块化机械臂控制模块：**完成机械臂关节驱动与末端位置控制，设计电阻 ID 识别电路实现夹爪/吸盘末端模块自动识别，完成手眼标定建立视觉坐标到机械臂坐标系的映射。

- **视觉感知模块：**基于 Orbbec Astra Pro 深度相机与轻量级目标检测模型（YOLO-tiny / MobileNetV3），实现颜色+形状双通道识别，通过手眼标定将像素坐标转换为机械臂工作空间坐标，完成静态目标的可靠抓取。

- **Agent 任务调度模块：**设计任务状态机（IDLE→NAVIGATE→DETECT→GRASP→TRANSPORT→PLACE），以行为树管理任务分解逻辑，实现底盘导航与机械臂抓取的协同调度与异常处理。

- **BCI 意图接入模块：**接入商用非侵入式 EEG 设备，采用专注度连续阈值触发策略（≥70/100 持续 2 秒触发 START 指令），将 BCI 意图信号接入 Agent 调度层。键盘保留为备用触发方式。

- **MR 空间反馈模块（核心创新）：**基于 Meta Quest 3 + Unity SDK 开发 AR 覆盖层，通过 ROS2 WebSocket Bridge 接收机器人位姿、规划路径、任务状态数据，实时渲染路径预览（Path Preview）和任务状态 HUD（Task Status），完成四层闭环的最后一环。

## **3.2  研究目标**

本课题的核心目标为：构建一套稳定可演示的"BCI × 具身智能 × MR"四层闭环工程融合原型系统，具体验收标准如下：

| **目标项** | **验收标准** |
| --- | --- |
| 底盘自主导航 | 室内点到点导航成功，动态避障有效，定位精度 ±10cm |
| 视觉抓取 | 识别并抓取桌面静态目标，成功率 ≥ 70% |
| 搬运全流程（无BCI/MR） | 完整搬运，手动触发，成功率 ≥ 80%，耗时 < 3 min |
| BCI 触发搬运 | EEG专注度阈值触发，端到端成功率 ≥ 70%，触发延迟 < 3s |
| MR 空间反馈 | Meta Quest 3实时显示路径预览与任务状态，刷新率 ≥ 10Hz |
| 四层闭环联调 | BCI触发+MR反馈完整闭环，端到端成功率 ≥ 70% |
| 模块化末端识别 | 夹爪/吸盘自动识别，Agent层无需手动配置即可切换策略 |

# **四、研究方案与技术路线**

## **4.1  四层闭环系统架构**

系统从上到下分为四层，各层职责明确，通过标准接口互联，共同构成认知-执行闭合回路：

| **层级** | **名称** | **核心功能** | **关键技术** |
| --- | --- | --- | --- |
| L1（意图层） | BCI 意图接入层 | EEG 信号采集，专注度阈值触发 START/PAUSE/ABORT 指令 | 非侵入式 EEG、Python SDK |
| L2（调度层） | Agent 调度层 | 任务分解、状态机管理、模块协调、异常处理 | ROS2 Action/Service、行为树 |
| L3（执行层） | 具身执行层 | 底盘导航、机械臂控制、视觉感知、末端模块驱动 | Nav2、MoveIt2、YOLO-tiny、I2C/CAN |
| L4（反馈层） | MR 空间反馈层 | 接收传感器数据，渲染路径/状态AR叠加层，闭环回传视觉反馈 | Meta Quest 3、Unity SDK、ROS2 Bridge |

闭环说明：操作者通过 Meta Quest 3 感知 MR 空间反馈（路径预览、任务状态）→ 调整注意力集中程度 → BCI 捕获专注度变化 → 触发或调节下一轮指令 → 循环。

## **4.2  总体技术路线**

- **支撑层先行：**优先完成驱动层与 ROS2 节点封装（底盘、雷达、IMU），建立稳定的硬件抽象层。底盘驱动已完成，下一步为 URDF 建模与 ROS2 节点封装。

- **MVP 渐进式迭代：**按"底盘自主→视觉抓取→系统集成→BCI接入→MR闭环"顺序推进，每阶段输出可独立验收的 Demo，降低后期集成风险。

- **接口契约优先：**所有模块通过约定的 ROS2 Topic/Action/Service 接口互联，接口定义一旦确定不随实现变化，保证模块可独立开发与测试。

- **分层调试工具：**已构建 FastAPI + SPA 调试面板，支持底盘实时控制、IMU 数据监控、雷达可视化，贯穿全开发周期加速调试效率。

## **4.4  软件技术栈**

- **机器人中间件：**ROS2 Humble，用于模块间通信（Topic/Action/Service/TF2）。

- **导航与建图：**SLAM Toolbox（激光雷达建图）+ Nav2（A* 全局规划 + DWA 局部规划）。

- **视觉感知：**OpenCV（图像处理）+ YOLO-tiny / MobileNetV3（轻量目标检测）。

- **操作臂控制：**MoveIt2（运动规划）或自定义逆运动学（依机械臂型号确定）。

- **MR 开发：**Unity + Meta Quest 3 SDK，通过 ROS2 For Unity 或 WebSocket Bridge 与 RDK X5 通信，渲染路径预览与任务状态 HUD。

- **开发语言：**Python 3.10（Agent 调度、BCI 接入、ROS2 节点）+ C++17（实时控制节点）+ C#（Unity MR 应用）。

# **七、可行性分析**

## **7.1  硬件可行性**

核心硬件平台已完成采购与初步调试：主控 RDK X5 已到位，底盘电机驱动、IMU（BNO055）、Orbbec Astra Pro 深度相机均已调通，RPLIDAR S1 串口通信已验证。机械臂待确认型号，不影响其他模块并行推进。Meta Quest 3 支持 Unity SDK 开发，硬件能力满足 AR 叠加渲染需求。EEG 设备商用 SDK 成熟可用。

## **7.2  软件可行性**

项目已建立完整的五层分层软件架构、日志系统、配置加载系统及 Web 调试面板，底层驱动代码质量较高（含单元测试脚本、SOP 文档）。ROS2 Humble、Nav2、MoveIt2 等框架均为成熟开源项目。Meta Quest 3 的 Unity SDK 提供了 C# API，与 ROS2 的 WebSocket Bridge 方案技术路径清晰。

## **7.3  时间可行性**

课题研究周期 12 个月，按 MVP 渐进式策略推进，各阶段均有可独立验收的交付物。即便 MR 闭环阶段因时间紧张无法完成，第四阶段的"完整搬运 Demo（手动触发）"本身已是具备完整展示价值的成果，不影响毕业设计的完整性。M6 四层闭环 Demo 是最大亮点，在时间允许的情况下优先推进。

## **7.4  主要风险与应对**

| **风险项** | **应对策略** |
| --- | --- |
| 机械臂型号待确认，控制方案不明确 | 优先明确型号；根据型号选择 MoveIt2 或自研 IK；不影响其他模块并行 |
| Meta Quest 3 SDK 适配困难 | 提前调研 SDK 文档与社区案例；备用方案：手机 ARCore 实现基础 AR 叠加 |
| ROS2 Bridge 与 Unity 通信延迟高 | WebSocket 直连优化；目标刷新率 ≥ 10Hz；降级为单向数据推送 |
| EEG 信号质量差，触发不稳定 | 设置 2s 判定窗口；键盘作备用触发；BCI 不影响前四个里程碑 |
| SLAM 建图漂移，导航定位失准 | 室内添加 AR 标记辅助；预存已知地图（仅定位模式） |
| 四层闭环联调复杂度高 | 按接口契约分层测试；每层独立验收后再上下游集成 |
| 单人开发，单点瓶颈风险 | 严格按 MVP 推进；M4 搬运 Demo 已是完整成果 |
